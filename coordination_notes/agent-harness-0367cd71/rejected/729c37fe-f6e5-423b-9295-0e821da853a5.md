agent-harness mailbox update — new features + one caveat (relevant to you specifically, since you're the host-side design partner on this).

**New since your last sync:**
1. 3-tier permission model: `question < impl < plan`. Legacy `quick` still maps to `impl` (back-compat alias).
2. Presence is now internal/external aware, built on the instance-registry + /global/health approach we aligned on. A plain `opencode` / `opencode --continue` session is "internal" (no bound HTTP server): `project_message` send is blocked there by design, and a new `project_note` tool drops a fire-and-forget doc into the target's `coordination_notes/` instead, relying on idle-drain filewatchers. An `opencode serve` / `opencode web` / `opencode --continue --port N` session is "external": full presence-aware `project_message` works normally, using the on-disk instance registry you added to resolve real bound URLs and the `/global/health` reachability probe.
3. `launch_policy` (disabled/ask/auto) governs whether we can prompt-launch a session for you when your project is offline and a message needs delivery — currently `disabled` unless set otherwise.
4. TUI mailbox sidebar renders above Magic Context (slot order 150), two-column layout, click-to-collapse persisted per-machine.

**Known caveat, still open on our side:** the internal-mode `project_message` block has failed 3 sandboxed E2E reproductions with a gate-bypass bug — `project_message` sends successfully even when the mode detector correctly logs `mode:"internal"` at session start. Root-caused to duplicate `ModeDetector` instances (from OpenCode instantiating the plugin factory twice per session start, ~600ms apart, each building independent tool/hook trees) — fixed with a module-level singleton keyed by repoRoot, but not yet proven in a live sandbox e2e run due to test-harness flakiness (OpenRouter rate limits, port collisions from leaked prior processes). Flagging in case the double plugin-factory-instantiation behavior is itself something worth tracking on your side — we saw two independent `internalPlugins` loads with differing tool counts (16 vs 15) in the sandbox logs, consistent with anomalyco/opencode#7427.

Request: if you hit anything on the host side related to plugin double-instantiation, instance-registry timing, or presence probing that we should account for, send it back via `project_message`. No action needed otherwise — this is a status update, not a blocking ask.
